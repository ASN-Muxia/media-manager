# TMDB 识别码优先解析（2026-10-07）

## 需求

优化文本（媒体文件名 / 标题）的解析识别规则：**在匹配标题、年份、分辨率之前**，
先检测文本里是否写了 TMDB 识别码。命中就以该 ID 作为唯一匹配依据、跳过模糊匹配；
未命中则回退原有流程，行为与输出格式不变。

## 二、关键改动点

### 2.1 唯一的解析入口

```rust
pub fn extract_tmdb_id(text: &str) -> Option<i64>
pub fn tmdb_id_from_texts(texts: &[&str]) -> Option<i64>   // 顺序即优先级
```

放在 `core/parser.rs`，文件名、标题、目录名都走这一处，规则只有一份，
避免各处各写一条正则彼此对不上。

`parse_stem` 的第 1 步（在去括号、**在任何标题/年份/季集/分辨率解析之前**）
改为直接调 `extract_tmdb_id(&norm)`。

### 2.2 正则

```rust
lazy_re!(re_tmdb, r"(?i)\btmdb(?:\s*id)?[\s\-_=:.]*(\d{1,10})\b");
```

| 写法 | 命中 |
| --- | --- |
| `tmdb-123456` | ✅ |
| `tmdbid:123456` | ✅ |
| `[tmdb=123456]` | ✅ |
| `(tmdb 123456)` | ✅ |
| `{tmdb_123456}` | ✅ |
| `TMDB.123456` / `tmdb123456` / `TmdbId = 123456` | ✅ |

三条防误伤设计：

1. **必须有 `tmdb`（或 `tmdbid`）关键字**。没有关键字的裸数字一律不算——
   `2012`、`1917`、`300勇士`、`50度灰`、`12怒汉`、`第01集` 全部安全。
2. **结尾 `\b`**：挡掉分辨率伪装。`tmdb 1080p` / `tmdb-2160p` 里的数字后面紧跟
   `p`，没有词边界 → 不认成 id（但 `tmdb-1080` 这种真 id 不会被误杀）。
3. **位数锁 1–10 位**：TMDB id 确实有 1–2 位的老片（`tmdb-7`），
   上限用来挡 `tmdb-12345678901234` 这种乱写。

### 2.3 刮削时的优先级链

`scrape_one` 第 1 步，新增纯函数 `tmdb_id_from_evidence()`：

```
1. explicit    调用方显式指定（手动匹配里用户勾选的那条）
2. stored      入库时已解析出来的（扫描时 parse_stem 写入 media.tmdb_id）
3. texts       现解析：原始文件名 → 标题
       ↓ 三者都没命中
4. pick_tmdb_id()   原有的「标题 + 年份检索，年份相等优先，否则取第一条」
```

命中 1–3 中任意一级就**直接作为唯一匹配依据**，
不再做基于标题和年份的检索式模糊匹配，也不会再去调大模型改标题重试（那段只在
`resolved.is_none()` 时才跑）。

> 这里接上了一个原有的断点：扫描入库时 `scanned.f.parsed.tmdb_id` **已经**写进了
> `media.tmdb_id`（`core/scanner.rs` 的 INSERT），但 `read_pending` 从来没读这一列，
> 所以刮削时明明知道 ID 却还去按标题+年份猜。现在把它读出来了。
> 第 3 级「现解析」是为了兼容历史存量数据——老数据入库时用的是旧版正则
> （不认 `tmdbid:` 这类写法），但文件名还在，能补回来。

### 2.4 未命中时行为不变

`tmdb_id_from_evidence()` 返回 `None` → `.or_else(|| pick_tmdb_id(...))` 走原路径，
后续详情回填、集数填充、豆瓣接管、`ScrapeOutcome` 输出格式**一行没动**。

改名为 `言叶之庭.2013.1080p.mkv` → 回退到原有的标题+年份匹配，结果与改动前一致。

## 四、踩到的坑

- 正则最初写 `(\d{3,})`，把 `tmdbid-7`、`tmdbid:42` 这类**短 id 漏掉了**——
  TMDB 确实存在 1–2 位的 id。改成 `(\d{1,10})` 后，靠结尾 `\b` 继续挡分辨率伪装。
