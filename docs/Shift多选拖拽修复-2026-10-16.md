# Shift 多选把聚合成员拖出来 —— 复现与修复（2026-10-16 · 第 16 轮）

用户报告：「现在在使用shift多选的时候会把已经在聚合里的电影拖拽出来，复现并解决这个问题」。

验证：tsc 0 错；vitest **29 文件 / 520 用例**（基线 28 / 513，新增 1 文件 7 条）。

---

## 一、复现（先复现，再改）

探针先跑出这条真实输出（`emit("move")` 真的被打出来了）：

    场景C  聚合模式(selectable=true, grouping=true) + selected=[11,12]
          按住 11 拖到 9 → move = [[{"ids":[11,12],"parentId":9,"index":null}]]

**聚合里的 11、12 被整批搬到了 9** —— 与用户描述一致。

## 二、根因

`App.vue` 的接线与 `PosterGrid` 的判据凑出一个危险组合：

    App.vue    :selectable = media.selecting || media.grouping
               :grouping   = media.grouping
    PosterGrid selectMode  = !!selectable && !grouping

**在聚合模式下**（`grouping=true`、`selecting=false`）：

| 判据 | 值 | 后果 |
| --- | --- | --- |
| `selectable` | **true** | 点击 / Shift 点击会**选中**（`onClick` 走 `select` 分支）|
| `selectMode` | **false** | 拖动 = **聚合搬运**（`beginPress` 生效）|

于是：用户 Shift 点选几张 → 它们进了 `selected` → 接着**手只要动过 6px**
（`DRAG_THRESHOLD_PX`，鼠标下按一下就必然抖过）就被判成拖拽 →
松手落在哪张卡上就 `batch = chosen.length > 1 && chosen.includes(id)` →
**整批 `emit("move")` 搬过去**。

关键认知：**这是手势歧义，不是数据错误**。同一张卡上「按下并微动」既可能是
「点选的余抖」也可能是「拖拽的起手」，6px 阈值分不开这两件事。

## 三、修法：带修饰键的按下一律不起拖

在 `beginPress` 最前面加守卫：

    if (ev.shiftKey || ev.ctrlKey || ev.metaKey) {
      dragArm.value = null;
      dragOrigin.value = null;
      return;
    }

语义与 **Windows 资源管理器**一致：
- **按着修饰键 = 在做选择**（Shift 区间 / Ctrl 单张切换），不搬动任何东西；
- **不按修饰键的拖动 = 搬动**（聚合 / 排序），行为完全保留。

为什么不会伤到别的路径：
- 「选择」模式的**滑动多选**（按住划过连续勾选）走不到 `beginPress` ——
  那条路径在 `onGridPointerDown` 里就被 `selectMode` 分支交给 `swipe` 了；
- **触摸没有修饰键**，不受影响（仍走长按起拖）。

## 四、验证

### 1) 单元用例（新增 `src/components/PosterGrid.shiftdrag.spec.ts`，7 条）
- Shift / Ctrl / Cmd 按住拖动 → **不发出 move**（3 条）；
- 已勾选一批后再 Shift 按住拖动 → 不发出 move（1 条，就是用户那条）；
- 反向回归：不按修饰键拖动 → 照旧 `move`（2 条）；
- 「选择」模式拖动 → 不 `move`（1 条）。

### 2) 变异测试：证明用例有牙齿（不是空转）
把守卫代码删掉（模拟修复前）再跑同一组用例：

    x Shift 按住并拖动：不发出 move
    x Ctrl 按住并拖动：同样不发出 move
    x Cmd(meta) 按住并拖动：同样不发出 move
    x 已勾选一批后，再次 Shift 按住拖动：不发出 move
    Tests  4 failed | 3 passed (7)

**恰好是那 4 条依赖守卫的失败，另外 3 条不受影响的照样通过** —— 用例确实钉住了这个 bug。
（恢复守卫后 7/7 通过。）

### 3) 真实浏览器（Edge + CDP，真实鼠标事件带 modifiers）

    Shift(8) 按住拖动       → moves = []                      OK（不搬动）
    Ctrl(2) 按住拖动        → moves = []                      OK（不搬动）
    不带修饰键拖动          → moves = [{ids:[11],parentId:9}]  OK（正常搬运）
    已勾选一批 + Shift 拖动 → moves = []                      OK（不搬动）

并确认**点击选择没被弄坏**（只挡了拖拽起手，没挡 click）：

    Ctrl 点击 11  → log: SELECT 11 shift=false ctrl=true
    Shift 点击 12 → log: SELECT 12 shift=true  ctrl=false
    selected=[11,12] 时 .card.picked 的 data-id = ["11","12"]   OK 高亮正确跟随

⚠️ 记一个**探针自身的坑**：我一开始用 `.cell.picked` 取高亮，连续得到空数组，
差点误判成「选择坏了」。实际上 `picked` 类挂在 **`.card`** 上（`PosterCard` 的根元素），
`.cell` 只是外层容器。**排查 UI 类名时先用 `document.querySelector` 确认真实结构**。

## 六、遗留

1. 守卫也意味着：**聚合模式下想整批搬不能按着 Shift 拖** —— 要整批搬就
   「先点选（可用 Shift 区间）、再松开修饰键拖」。这与资源管理器一致；
   若用户希望「Shift 拖 = 搬整批」，需要另定语义（当前按用户报的问题优先保证不误搬）。
2. 触摸没有修饰键概念，**触摸下无法区分「点选余抖」与「拖拽起手」** ——
   目前靠长按（350ms）区分，与滑动多选同一套约定。
3. 本轮仍未 `git add`。
