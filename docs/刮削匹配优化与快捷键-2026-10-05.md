# 刮削匹配优化 + 候选面板改造 + 快捷键与顶部吸附（2026-10-05）

本轮包含两个需求，共用同一套新设置项，一起落地：

1. **手动匹配候选太少 + 下拉难用** → 放开数量上限、改成可筛选可勾选的弹窗面板。
2. **刮削关键词识别与筛选优化** → 多语言标题匹配、模糊匹配、年份/季数辅助、黑名单排除、优先级规则；
   外加**可自定义快捷键**与**顶部工具栏吸附**。

## 三、关键改动点

### 3.1 为什么单独抽 `core/matching.rs`

原来自动刮削只做「年份相等就取，否则取第一条」（`pick_tmdb_id`），手动匹配更是把 TMDB 原样结果
直接丢给界面。四个具体毛病：

- 译名不同就对不上（`The Garden of Words` ↔ `言叶之庭`）——**原标题没参与比对**；
- 多了个副标题、少个空格就掉 0 分——**没有模糊匹配**；
- 同名不同年份的片子排在前面——**年份只是过滤器，不是打分项**；
- 想排除「剧场版 / 演唱会 / 幕后花絮」只能手挑——**没有黑名单**。

新层把这四件事做成可配置、可单测的纯函数。

**刻意不做的事**（写在模块头注释里）：

- **不认识 `TmdbSearchItem`**：本层只吃字符串，保证 `core` 不反向依赖 `provider`（分层红线 B3），
  用例也不用造网络结构体；
- **不参与「要不要刮削」的决策**：只回答「哪个候选更像」；
- **分辨率不参与打分**：TMDB / 豆瓣的候选里根本没有分辨率字段，硬编进分数只会制造假信号。
  分辨率只用来**清洗检索词**（`strip_tech_tags` 去掉 `1080p` `x264` `HDR` 之类）。

### 3.2 优先级规则（可调）

| 命中类型 | 权重 |
| --- | --- |
| 展示名归一化后完全一致 | 100 |
| 原标题 / 别名完全一致 | 90 |
| 一边包含另一边（副标题、续作标记） | 55 |
| 模糊匹配（按相似度缩放，下限 0.72） | 45 |

修正项叠加：年份命中 **+20**、年份超出容差 **−30**、季数推断吻合 **+8**、评分最多 **+6**。

黑名单是**整条剔除**（不是扣分）：候选标题里出现任一个排除词就 `excluded=true`，
`keeps()` 直接判掉，并在 `match_reasons` 里写明被剔的原因。

### 3.3 候选数量：20 → 60（上限 200）

TMDB 每页固定 20 条，用户想要的那个常常就在第 21 条之后，只能反复改关键词碰运气——
这就是「候选太少」的由来。新增 `search_many()` 翻页抓取并按 TMDB id 去重，
`DEFAULT_LIMIT=60` / `MAX_LIMIT=200`，两者由设置项与命令共用同一份常量，避免两处各写一个数字。

**兜底**：带上年份检索可能因本地年份不准而一无所获，此时**退一步不带年份再试一次**。

界面侧列表**滚动分页 30 条/批**，首屏只渲染 30 个 DOM，但顶部计数显示的是全量候选数，
避免一次性渲染 200 行卡顿。

### 3.4 返回格式保持向后兼容

`search_tmdb` 仍返回 `Vec<TmdbSearchItem>`，只**新增**了 `originalTitle` / `originalName` /
`matchScore` / `matchReasons` 四个可选字段。老调用方不用改。

### 3.5 快捷键

默认：`Ctrl+A` 全选 / `Ctrl+Shift+A` 反选 / `Ctrl+Enter` 确认刮削所选 / `Esc` 清除选择。

- `useHotkeys` 全局监听 `document` 的 keydown；
- **焦点在 `input` / `textarea` / `select` / `contenteditable` 时一律跳过**（否则在搜索框打字就触发全选）；
- 有 `active` 门控，弹窗打开时只响应弹窗自己的绑定；
- 设置页里点输入框**直接按键捕获**组合，不需要手打字符串。

### 3.6 顶部吸附

`App.vue` 里把 `.topbar` 和 `.selbar` 包进同一个 `.stickytop`（`position: sticky; top: 0`）。

> ⚠️ 这里有个坑：**两个 sticky 元素都写 `top:0` 会互相压住**，所以必须共用一个吸附容器，
> 而不是各自 sticky。

`TmdbMatchDialog` 12 条。

### 4.2 手动验证清单

**筛选**

1. 打开任一条目 → 「手动匹配」，弹窗出现即自动用条目标题检索（不用手点）。
2. 顶部显示「共 N 个候选」；N 明显大于 20（说明数量上限已放开）。
3. 滚到底会再加载一批（30 → 60），不卡顿。
4. 关键字框输入：
   - 中文片名 → 命中；
   - **英文原标题**（如 `The Garden of Words`）→ 命中同一条，验证跨语言；
   - 年份 `2016` → 命中；
   - TMDB id → 命中。
5. 勾上「只看有海报」/「只看年份吻合」，行数即时减少，且**不再发网络请求**（纯本地过滤）。
6. 改「年份容差」下拉 → 等约 0.4 秒会**重新检索**，且新容差确实传给了后端。

**选择**

1. 点一行选中，行高亮，底部显示「已选：TMDB #xxx」；再点一次取消。
2. 选另一条会顶掉前一条（单选）。
3. 没选时「应用所选」是禁用态；选了以后点它 → 开始刮削并关闭弹窗。
4. 检索失败（比如没填 API Key）会**把错误显示出来**，而不是给一个空列表骗人。

**快捷键 / 吸附**

1. 在封面墙多选状态下：按 `Ctrl+A` 全选、`Ctrl+Shift+A` 反选、`Ctrl+Enter` 刮削所选、`Esc` 清除。
2. 焦点在搜索框里打字时，**不会**触发上面任何一个。
3. 设置页可以改这几个组合，改完按钮上的角标同步更新。
4. 页面滚动时顶部工具栏（含全选/反选/刮削所选）**始终可见**。

## 五、踩过的坑（别再踩）

1. **Pinia setup-store 新 ref 必须加进 `return {}`**。本轮 `matchYearTolerance` 漏了，
   组件读到 `undefined`，`Math.max(0, undefined)` = `NaN`，年份筛选**静默放过一切**，
   看起来像「筛选功能没实现」。
2. **`watch(() => props.open, ...)` 要带 `{ immediate: true }`**。弹窗是「挂载时就已经打开」的，
   没有 immediate 的话首次检索永远不跑，表现为列表一片空白。
3. **测试数据要让断言唯一**：按 TMDB id 过滤的用例别把 id 写成 `1/2/3`，
   「102」会命中 1024 之类，改成 `101/102/103`。
4. **`strip_tech_tags` 别用字节下标切 Unicode**，会 panic。改成按 token 切分
   （CJK / ASCII 词 / 分隔符），拼接时用 `needs_space` 决定要不要补空格。
5. 打分时发现 **`alias` 权重根本没被用上**（`pair_score` 一律取 `exact`），
   是测试先红才暴露的——顺手修成：展示名用 `exact`，原标题/别名用 `alias`。
