# 滑动多选：历史对比、恢复与修复记录（2026-10-05）

本文记录本轮对「滑动多选」的考古、恢复与 Bug 修复。目标：完整恢复历史版本的
滑动手势能力，并与当前代码结构、交互风格保持一致。

## 一、历史实现 vs 当前实现的差异

考古方式：`git log` / `git show` 回溯 `src/utils/dragSelect.ts` 与
`src/composables/useSwipeSelect.ts` 的历史版本（关键提交 85a7c08、fb1ffdc）。

### 结论先行：核心状态机「一行没丢」

`utils/dragSelect.ts` 里的状态机（`beginDragSelection` / `applyDragTo` /
`finishDragSelection` / `toggleOne` / `dragTrigger` / `edgeScrollSpeed`）**从未被删除**，
历史上只是从 98 行（85a7c08）增强到 165 行（fb1ffdc）。所以这不是一次「功能被误删」，
而是一次**能力分发不均 + 两处共同缺失**。

### 差异表

| 能力 | 历史版本 | 本轮修复前 | 说明 |
|---|---|---|---|
| 状态机 | 有 | **有** | 未丢失，本轮零改动 |
| 封面墙：拖选 / 框选 / 抹掉 | 有 | 有 | 保持 |
| 封面墙：`elementFromPoint` 兜底 | **有** | **退化掉了** | jsdom 无此 API → 旧实现 TypeError 炸掉整条链路 |
| **快速滑动补齐被跳过的项** | 缺 | **缺** | 两处**共同**缺失：两次 `pointermove` 之间跨过的项不会被选中 |
| **首尾项端点夹取** | 缺 | **缺** | 两处**共同**缺失：划到列表上/下方之外会漏掉首项或末项 |
| 详情页：长按 350ms 起手 | 有（封面墙） | **缺** | 详情页是内联实现，fb1ffdc 只给封面墙加了新能力 |
| 详情页：跳过行 / 端点夹取 | — | **缺** | 同上 |
| 详情页：尾随 click 吞除 | 有（封面墙） | 缺 | 拖动结束后浏览器补发的 click 会把刚选中的行又切回去 |
| 边缘自动滚动 | 有 | 有，但两处各写一份 | 本轮抽成共用 `useEdgeScroll` |
| 行内控件判定（`pressBlocked`） | 内联 | 内联 | 本轮抽成共用导出 |
| `pointercancel` 语义 | 当作正常松手提交 | 同左 | **这是 Bug，见下** |
| `touchmove` 注册方式 | — | 模板 + 命令式**双份** | **这是 Bug，见下** |

**一句话概括病根**：fb1ffdc 把新能力只接给了封面墙，详情页原地踏步；
而两处又共同缺「补齐跳过的项」和「首尾端点夹取」——这两条正是用户明确点名的
「快速滑动」与「首尾项」边界情况。

### 关键修改点

**1）快速滑动 —— 补齐被跳过的项**
新增 `applyDragRange(state, order, fromIndex, toIndex)`：把两次 `pointermove`
之间**被跨过的项整段补齐**。支持反向（往回拖）、幂等（同一区间重复调用不翻转）、
下标先 `clamp`。

**2）首尾项 —— 端点夹取**
新增 `clampIndex(index, length)`（越界夹到首/末项，空列表返回 `-1`）；
`clampOutside(clientY)` 在划到列表上/下方之外时把命中点夹到首/末项，
`rect.height <= 0` 时返回 `null` 优雅退化（jsdom 无布局引擎）。

**3）手势冲突**

- **鼠标按下即起手**，历史语义保留，**刻意不加位移阈值**——加了会破坏
  「按下再松手切换单行」这个既有行为。
- **触摸必须长按 350ms**（`LONG_PRESS_MS`）才进入多选；手指先动 = 用户在滚页面
  → `abortPending()` 放弃，不产生任何选中。
- **行内控件**：`pressBlocked(target, itemSel, blockSel)` —— 只有选项元素
  **内部**的控件才算被拦，**选项自身永远不算**（把 `button` 写进 `blockSelector`
  也不会让拖动起不来）。`onPointerDown` 改为**先找 row 再判 block**（原来反了）。
- **尾随 click 吞除**：`armSwallow` 只在**真的拖动过**时才装，捕获阶段一次性拦截。

**4）几何命中**
触摸走 `document.elementFromPoint`（并补回 `typeof !== 'function'` 兜底，
jsdom 无此 API）；鼠标走 `event.target` —— 触摸**不能**退回 `target`，
隐式指针捕获会让 target 卡在起点。

**5）边缘自动滚动**
抽成共用 `useEdgeScroll(onFrame)`（找滚动祖先 + rAF 循环 + 每帧回调），
消灭两处拷贝。

## 三、修掉的三个 Bug

### Bug 1（P0）`touchmove` 监听根本没挂上

- **现象**：触摸下长按进入多选后一拖，页面跟着一起滚。
- **根因**：根节点是 `v-if` 出来的（封面墙在**空库时根本不渲染** `.grid`），
  首次挂载时 `o.root.value === null`，`el?.addEventListener` 静默跳过；
  而 `onMounted` **不会再跑第二次** —— 等扫描完数据来了、网格渲染出来，
  监听**永远补不上**。
- **修法**：`watch(o.root, (el) => bindTouch(el), { flush: "post" })`，
  监听跟着根节点换绑；`bindTouch` 内 `if (touchEl === el) return` 去重、换根先摘旧的。

### Bug 2（P0）`pointercancel` 误把半截选择提交上去

- **现象**：系统打断手势（来电、手势导航、多指介入）时，拖动到一半的选择被当成
  正常松手**提交**了。
- **修法**：语义从「提交」改为「**放弃并回滚**」。
  - `useSwipeSelect.ts`：`end()`（唯一写回外部处）vs `cancel()`（不调 `commit`、
    **不装 click 吞除**）；`pointerup → end`、`pointercancel → cancel`，卸载时都摘。
  - `MediaDetail.vue`：`dragSnapshot` 在 `beginEpDrag` 的 `syncFromDrag()`
    **之前**拍（时机关键）；`endDrag()` 提交、`cancelDrag()` 回滚到快照、
    `abortDrag()` 用于换条目/卸载。
  - 关键约定：快照**只能回滚本次拖动**，起手前已勾选的行必须保留。

### Bug 3（P2）`onTouchMove` 被注册两份，每个 touchmove 跑两次

- **根因**：模板 `@touchmove`（Vue 注册的是它自己的 **invoker 包装函数**）
  与模块内 `bindTouch()`（注册 `onTouchMove` **本体**）**引用不同** →
  DOM 按 `(type, callback, capture)` 去重时**不会合并** → 两份都生效。
  用 `vi.spyOn(event, 'preventDefault')` 实测每个 touchmove 调用 **2 次**。
- **影响**：当前无（`onTouchMove` 只有一句幂等的 `preventDefault`）。
  **隐患**：将来若加入非幂等逻辑（记录指针位置、累计偏移）会静默跑两遍且极难排查。
- **修法**：**删掉模板绑定，`onTouchMove` 从对外 API 撤掉**，注册由 `bindTouch`
  独占 —— 让重复注册**在结构上不可能发生**，而不只是靠注释提醒。
  同时用一条用例钉住「返回值不含 `onTouchMove`」，防止以后图方便又导出回去。
- **注意**：这个 ×2 **不是泄漏**。换绑后触发次数与首次挂载基线一致，
  说明旧节点监听确实摘干净了。

### 针对性用例（每条都写明命中哪条规则）

| 场景 | 断言要点 |
|---|---|
| 快速滑动 | 一次大跨度 `pointermove` 后，中间被跳过的项**全部**被选中；反向拖动同样成立 |
| 首尾项 | 划到列表上/下方之外，首项 / 末项仍被选中；反向亦然 |
| 首尾项（重复划过） | 幂等：反复划过同一区间不会翻转选中态 |
| 长按 vs 滚动 | 手指先动 → 不起手、不产生选中；按住 350ms 再动 → 起手 |
| 鼠标按下松手 | 仍能切换单行（**刻意不加位移阈值**的回归防线） |
| 行内控件 | 选项自身的按钮被写进 `blockSelector` 也不影响起手 |
| `pointercancel` → 放弃 | 回滚到拖动前；**已勾选的历史行保留** |
| `pointerup` → 提交 | 同串动作走 `pointerup` 仍正常提交（与上条做**对照**，防两条路径被合并回去） |
| click 吞除 | `pointerup` 后尾随 click **被吞**；`pointercancel` 后**不被吞**（对照） |
| touchmove 换绑 | 空库 → 有数据 → 清空 → 再填充，监听跟着换、无泄漏、次数与基线一致 |
| touchmove 不重复 | 返回值不含 `onTouchMove`；每个 touchmove 只处理 **1 次** |

### jsdom 限制说明

jsdom **没有** `PointerEvent`、**没有** `elementFromPoint`、**没有**布局引擎
（`getBoundingClientRect` 不可断言真值）。因此：
几何命中走注入桩，不用真实坐标断言；`elementFromPoint` 在源码里有
`typeof !== 'function'` 兜底，测试里用可注入实现覆盖两条分支。
