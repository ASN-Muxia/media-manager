## 一、资源目录库（新增，SCHEMA_VERSION 6 → 7）

### 为什么不能并进「媒体库扫描」

`scan_library` 回答的是「用户有哪些**作品**」：它会新建 / 归并 / 改挂 `media`、`episodes` 行，
条目还会被「重新识别」改写类型。而用户要的是另一个问题：**「盘上到底有哪些文件，
和上次比变了什么」**。作品行在「识别不出来」时压根不存在，文件被挪走后更会从条目层消失
—— 所以必须有一份**以绝对路径为身份、只增不删**的清单。

### 两张新表

| 表 | 作用 |
| --- | --- |
| `resource_assets` | 一个文件一行。`path` 有 UNIQUE 索引，upsert 幂等。 |
| `resource_snapshots` | 每次检测的汇总（扫描/新增/更新/未变/丢失/恢复 + 起止时间）。 |

🔑 **核心设计：`status='missing'` 的行永不删除。** 文件消失只把状态翻成 `missing` 并记
`missing_at`，行本身留着 —— 这正是「定位旧资源」的落点：它上次在哪、多大、什么时候不见的，
全都还查得到。文件回来时置回 `present`（`Restored`），`first_seen` 永不被覆盖。

### 分层

- `core/registry.rs`（**纯函数、不碰 IO/DB**）：
  `AssetFingerprint{size,mtime}` / `AssetChange{New,Unchanged,Modified,Restored}` /
  `classify(prev, now)` / `reconcile(existing, seen)`。
- `commands/registry.rs`：取设置 → 遍历磁盘 → 套规则 → 写库。
  **遍历（`walk_media_files`）与入库（`apply_catalog_sync`）刻意拆成两个函数**，
  否则每个单测都要依赖用户真实的媒体目录。

### 三条判定（与 `core/diff.rs` 同一原则：宁可保守）

- 库里没有这个路径 → `New`；
- 库里标着 `missing`、这次又看到 → `Restored`（**排在指纹比较之前**：文件回来了这件事
  比"大小变没变"更该被单独计数）；
- `size` 或 `mtime` 变 → `Modified`；**任一侧取不到 mtime 就保守当成 `Modified`**。

🔑 **reconcile 绝不能把"本次没遍历到的行"一股脑标 missing**：盘没挂上、某个根目录被删时
整盘都会判成消失，那是灾难性误报。所以调用方只把**本次真正走通的根目录下**的行交进来；
且范围按**路径前缀**（卡分隔符边界）而不是库里的 `root_path` 字符串 —— 用户把媒体目录
从 `D:\media` 改窄成 `D:\media\movies` 之后，老行不会永远停在 `present` 而让线断掉。

### 三个命令

| 命令 | 返回 | 用途 |
| --- | --- | --- |
| `sync_resource_catalog` | `CatalogSyncResult` | 「检测资源库」：遍历 + 增量写库 + 记快照 |
| `get_resource_catalog(limit,status,keyword)` | `CatalogEntry[]` | 清单（LEFT JOIN media 补作品名） |
| `diff_resource_catalog` | `CatalogDiff` | 与上一次对比：新增 / 变化 / 丢失 |

前端字段名（camelCase，已有用例钉死）：
`CatalogEntry` = id, path, **fileName, relDir, rootPath**, size, mtime, status,
**mediaId, displayTitle, mediaType**；
`CatalogSyncResult` = **startedAt, finishedAt**, roots, scanned, added, updated, unchanged,
missing, restored, message；`CatalogDiff` = added, changed, missing, present, **lastSyncAt**。
⚠️ **`CatalogEntry` 没有 ext 字段**（契约未列，刻意没加）。

`changed` 的口径：`first_seen <= 上次快照` AND `mtime > 上次快照`，即「上次检测时就见过、
之后被文件系统改写过的文件」。**不能用 `last_seen`** —— 每次检测都会给见到的每一行刷
`last_seen`，那个判据会退化成「盘上全部文件」。已知取舍：mtime 取不到的文件不进 `changed`
（宁可少报，不假报）。若要「被判为 Modified 的那些行」需要新增一列 `last_change`，本轮没有。

### 前端

- `src/api/commands.ts`：`CatalogEntry` / `CatalogSyncResult` / `CatalogDiff` / `CatalogQuery`
  + `syncResourceCatalog()` / `getResourceCatalog()` / `diffResourceCatalog()`（只追加）。
- `src/components/LibraryCatalog.vue`：**无 props / 无 emits**，`defineExpose({ refresh })`。
  三块：同步摘要（6 个数字 + 最近同步时间）/ 变更对比（新增·变化·丢失三组）/
  可筛选清单（丢失行 `tr.is-missing` + `.tag-missing` 明显区分）。
  🔑 **组件自己不存「是否已同步」**（不写 localStorage / store）：真实来源是后端
  `resource_snapshots`，前端再存一份两边迟早对不上。
- 入口：侧边栏「🗄 资源目录库」（`VIEW_CATALOG`）。切到它时 `onNav` **提前 return**，
  不查媒体列表，也把搜索 / 排序 / 选择 / 聚合那几个控件一起收起来 —— 它们筛的是「作品」，
  与这份「磁盘文件清单」无关。

## 二、顶栏「选择 / 聚合」按钮不再消失

原实现：

```html
<button v-if="!inSettings && !media.selecting" ...>☑ 选择</button>
<button v-if="!inSettings && !media.grouping" ...>🔗 聚合</button>
```

点进去之后按钮**整块被摘掉**：用户既看不出"我正处于这个模式"，也找不到原路退出的地方
（只能去工具条最右边找那个「退出选择」）。改成**常显的开关**：开启时 `btn-primary` 高亮 +
`aria-pressed=true` + 文案变「退出选择 / 退出聚合」，点一下即关闭；两个模式仍然互斥
（`enterSelecting` / `enterGrouping` / `exitGrouping` 互相收口）。

用例：`src/App.toolbar.spec.ts`（8 条，含「开启后按钮仍在」「互斥切换」「目录库视图下让位」）。

## 三、拖动禁止光标 + 资源管理器式拖放（根因与改法）

### 根因（有真实浏览器证据）

原实现走 HTML5 原生 DnD，而：

1. `const idleDraggable = computed(() => !!props.grouping)` 绑定在 `:draggable` 上 ——
   **默认（普通）模式下整墙没有任何可拖元素**，用户最直觉的「按住海报拖到另一张上」
   根本不产生 `dragstart`，表现为"拖不动"。
2. 原生拖拽必须由一个 `draggable` 元素起手，而 `draggable` 只能在 `pointerdown` 里决定；
   于是「卡片恒可拖」与「按住划过 = 滑动多选」在**同一个手势**上直接冲突，只能二选一。
3. 原生拖拽一旦启动，浏览器就掐断 pointer 事件流并补一次 `pointercancel`，滑动多选当场失灵。
4. 🔴 **光标完全由浏览器判**：`<img>` 天生可拖、卡片标题文字可选，按住它们拖起来的是
   **图片拖拽 / 文本拖拽** —— 载荷是图片 URL 或一段文字，鼠标上画的正是那个"禁止"图标，
   放下什么都不发生。它跟"目标拒绝接收"长得一模一样，这就是用户反复看到的 🚫。
5. 落点反馈也被浏览器接管：非法落点只能画禁止光标，给不出"为什么不行"。

### 改法：改成**指针驱动的自绘拖拽**（不再用原生 DnD）

- 卡片上**一个 `draggable` 都不留**；`PosterCard.vue` 的海报图写死 `:draggable="false"`
  （写死而不是在 pointerdown 里现改：浏览器在**还没按**的时候就已经把那张图当可拖源了），
  CSS 里 `-webkit-user-drag: none` 作第二道保险。
- 起手判定归自己（`DRAG_THRESHOLD_PX`）。🔑 **手势分配用 `selectMode = !!selectable && !grouping`**：
  **默认 / 聚合模式 = 拖动**，**「选择」模式 = 连续勾选**（滑动多选逻辑未改）。
- 🔴 **曾经的设想已被真实浏览器证伪**：「先按滑动多选走、指针明确跨到别的卡片之后才改判成拖拽」
  **在浏览器里行不通** —— 滑动多选划 1→2→3 本身就是「跨了几次卡片」，会被当场改判。
  CDP 实测（默认模式按住第 1 张划过第 3 张）：只发出 `MOVE{ids:[1],parentId:3}`，没有 `SELECT_MANY`。
  同一个手势不可能既是「搬走」又是「勾选」，只能靠顶栏「选择」这个明确意图分流。
  **代价**：默认模式下想「按住划过一串卡片来勾选」必须先点「选择」。这与 Windows 资源管理器一致
  —— 按住一拖 = 搬动，框选要先进入选择态。
- 落点用 `document.elementFromPoint` 命中；光标 / 落点高亮 / **非法原因文字**全由界面给
  （`canDrop` 的 `reason`），不再是"目标不可接收"。
- 跟手预览（`.ghost`）自己画：指针驱动的拖拽没有浏览器自带拖影，
  不画就等于"按住一拖屏幕上什么都没发生"。
- 触摸一并受益：HTML5 拖拽在触摸下压根起不来，指针驱动没有这个问题。

### 真实浏览器实测（Edge headless + CDP，Node 22 自带 WebSocket 驱动）

把**未改动的真实 `PosterGrid.vue`** 挂进 harness，用 `Input.dispatchMouseEvent` 走
「按下 A → 分 8 步移动 → 在 B 上松开」，读回组件有没有真的发出 `move`：

```
===== 默认模式（用户不开任何开关） =====
  发出 move = true
    | MOVE_EMITTED {"ids":[1],"parentId":2,"index":null}

===== 聚合模式（顶栏开关开启） =====
  发出 move = true
    | MOVE_EMITTED {"ids":[1],"parentId":2,"index":null}
```

两个模式都能拖放。⚠️ 排查时踩到的坑：**改完源码必须先 `Page.reload({ignoreCache:true})`**，
否则 Vite HMR 保留旧组件实例，会看到"聚合模式仍然拖不动"的假阴性。

（harness 文件 `harness.html` / `harness-main.ts` 与子代理自己的 `dnd-*` 探针、`run-probe.mjs`
都已在收尾时从项目里删除。）

## 五、未做的取舍 / 遗留

1. `diff_resource_catalog` 的 `changed` 用「上次快照之后 mtime 被改过」近似；
   要精确到"每次检测被判 Modified 的那些行"需加一列 `last_change`。
2. 目录库清单**未做分页 / 虚拟滚动**（`limit` 参数已透传但组件不传），
   历史积压极大时表格会很长；关键字**未防抖**（本地 SQLite LIKE 很快，与项目
   「筛选在 SQL 层」一致）。
3. 摘要数字只活在组件内存里：刷新页面后为空，但「最近同步时间」来自后端对比结果、始终真实。
4. `commands/registry.rs` 里复制了一份 `core/scanner.rs` 的 `is_skippable_dir` 口径
   （那个函数是私有的，没为它改 `core` 可见性）。要消除重复需放行 `core/scanner.rs`。
5. 本轮**未 commit**（与上一轮「内容聚合改造」一样留在工作区）。⚠️ 但打包走
   `git ls-files`，**发行前必须把本轮文件 `git add`**，否则新文件进不了包。
6. 前端改了必须重新 `cargo build`（前端编译期嵌进 exe），本轮只跑了 `vite build` 与
   `cargo test`，**没有重新构建 release exe** —— 要出包/启动前需补 `cargo build`。
7. **默认模式下「按住划过一串卡片勾选」不再可用**，必须先点顶栏「选择」（见第三节的
   `selectMode` 说明）。这是为满足「默认状态下直接拖」而做的必要取舍，改变了上一轮
   刚交付的默认体验 —— **若产品上不接受，需要另行决策**（例如在「选择」模式里补一条
   「按住已有勾选项 = 拖走整批」的旁路）。
8. 拖放本身：**触摸拖放无真机证据**（只有 jsdom 用例；代码按「长按起拖、未长按先划 = 放弃」实现）；
   **多指针未处理**（`dragArm`/`dragIds` 是组件级单例）；**不再支持跨窗口拖拽**（自绘拖拽 +
   移除了 `text/plain`，将来要「拖到资源管理器 = 复制」需重新引入 `setData`）；
   **拖到窗口上下边缘不会自动滚动**；**落点只判「放进内部」**（`before`/`after` 在界面不可达，
   这是既有行为，拖动不能用来排序，排序仍走详情页 ↑↓）。
