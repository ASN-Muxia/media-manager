# 同目录同片：多个视频文件归并成一条条目（2026-10-05）

## 1. 现象

`D:\动画电影\[VCB-Studio] Kotonoha no Niwa [Hi10p_1080p]\` 下有

```
[VCB-Studio] Kotonoha no Niwa [Hi10p_1080p][x264_flac].mkv   ← 3.37 GB
[VCB-Studio] Kotonoha no Niwa [Hi10p_1080p][x264_flac].mp4   ← 1.29 GB
SPs\……[CM]…mkv / [IV]…mkv / [Menu]…mkv / [PV]…mkv / [SP]…mkv
```

方括号被 `strip_all_groups` 剥掉后，这 7 个文件解析出的标题**全都是**
`Kotonoha no Niwa`。旧逻辑里电影 / 待确认是「一条一个实体」，于是墙上出现
一排同名卡片。

## 2. 根因

`core/scanner.rs` 的 `apply_group_plan` 只处理剧集，注释写得很明白：
「电影一条一个实体，不需要归组」。入库循环因此对每个 `Movie / Unknown`
文件各调一次 `insert_single`，几个文件就是几条 `media` 行。

## 3. 改动（只动必要模块）

| 文件 | 改动 |
| --- | --- |
| `src-tauri/src/core/scanner.rs` | 新增 `MovieVersionPlan` / `MovieVersionGroup` / `plan_movie_versions()`（纯函数，不碰库）；新增 `insert_version()`、`media_id_by_path()`、`carry_metadata()`、`drop_scattered_row()`、`import_movie_versions()`；`import_reported()` 的电影分支改为「整组处理」；`ScanStats` 增加 `versions` / `added_versions` / `merged_entries` |
| `src-tauri/src/commands/media.rs` | `added` 计入 `added_versions`；导入与扫描的提示语补上「N 个同片文件并入同一条目 / 合并 N 个重复条目」 |
| `src/components/MediaDetail.vue` | 电影 / 待确认条目下的多文件来源显示为「其它版本 / 文件来源」（不叫「第 N 季」），计数写「共 N 个版本」 |

### 数据模型（没有新表）

- **主体**：一组里最好的那份写进 `media.file_path` / `file_name` / `file_size`
  → 详情页「▶ 播放」直接播它，这就是**默认播放版本**；
- **版本**：其余每份文件写一条 `episodes` 行，`season = 0`、`episode` 递增，
  `title` 写**文件名**（版本之间解析出的标题完全一样，只有文件名能区分），
  `resolution` / `release_source` / `file_size` 各自保留。

`season = 0` 不会和剧集特辑混淆：那条 `episodes` 的 `media_id` 指向的是
`type IN ('movie','unknown')` 的行，剧集是 `type = 'tv'`。

### 主体竞选（默认播放版本怎么定）

组内按 `电影 > 待确认 → 分辨率高 → 体积大 → 下标小` 排序取第一。
分辨率优先看增强层填的 `resolution`，没填就退回文件名里的 `2160p / 1080p…`。
分辨率和体积都认不出来时退化为「下标最小」，结果仍然稳定（可重扫）。

## 4. 影响的逻辑分支与回归场景

| 场景 | 行为 | 用例 |
| --- | --- | --- |
| 单文件目录 | **不产出任何组**，走原来的 `insert_single` 路径，逐字等价 | `single_file_dir_has_no_version_group` |
| 同目录同片多文件 | 一个条目 + N-1 个版本；默认播放版本 = 画质最好的那份 | `same_dir_same_movie_becomes_one_entry_with_versions` |
| 同目录不同片 | 归一化标题不同，各自独立 | `same_dir_different_movies_stay_apart` |
| 同目录同片但年份冲突 | 整桶放弃归并（重拍 / 不同年份版本，宁可不并） | `same_title_conflicting_years_are_not_merged` |
| 跨目录同名 | 不合并（目录是最强归属证据） | `same_title_across_dirs_is_not_merged` |
| 重扫 | `ON CONFLICT(file_path) DO NOTHING` + 版本号顺延 → 幂等 | `rescan_after_merge_is_idempotent` |
| 存量多头条目 | 重扫时收编：先搬元数据、再删多余行 | `legacy_scattered_movie_rows_are_merged_on_rescan` |
| 用户改过的条目 | `locked = 1` / `source = 'manual'` 一律保留不删 | `locked_scattered_row_is_not_deleted` |
| 被删条目有元数据 | 只补主机**缺的**字段（tmdb_id / 海报 / 背景图 / 简介 / 流派），绝不覆盖 | `metadata_of_merged_row_is_carried_to_host` |

### 与剧集相关的分支不受影响

- `plan_movie_versions` 只吃 `Movie / Unknown`，`Tv` 一个都不进；
- `apply_group_plan`、`upsert_series`、`insert_episode`、`repoint_episode`、
  `drop_empty_series_shells` 全部没动；
- 编号共识（R7/R8）判成剧集的目录仍然走剧集链路。

## 5. 真实文件名实测（临时探针，已删）

把上面 7 个真实文件名喂进 `collect_files → plan_movie_versions → import`：

```
收集 7 个文件（5 个判成 Unknown、1 个判成 Tv（[SP] 命中特辑规则）、1 个 mkv）
归并后：3 条 media 行
  #1 unknown  Kotonoha no Niwa（SPs/CM） + 3 个版本（IV / Menu / PV）
  #2 tv       Kotonoha no Niwa           + 1 集（SP，第 0 季）
  #3 unknown  Kotonoha no Niwa（根目录 mkv） + 1 个版本（mp4）
```

即：根目录的 `mkv + mp4` 从「2 张同名卡片」变成「1 条条目 + 1 个版本」；
`SPs` 目录从 5 张卡片变成 2 条。`[SP]` 被判成剧集特辑是既有的判定行为，
本次没有改动。

## 7. 已知边界

- 跨目录的同片多版本（如 `…\1080p\x.mkv` 与 `…\4K\x.mkv`）**不**归并——
  目录是最强归属证据，跨目录同名很可能是两部片子。
- 收编存量条目时只删「自动扫描出来的、用户没动过的」行；用户改过的会保留，
  此时那份文件既作为版本出现、也保留原来的独立卡片（宁可重复，绝不误删）。
