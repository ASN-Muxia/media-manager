# 第二轮开发记录（2026-10-04）：架构落地 + 视频文件只读

本轮目标：把 `docs/影视管理软件架构规划与任务分工总览-2026-10-04.md` 里规划的能力真正落地，
同时严格守两条红线——**主体功能（B1–B8 边界）不变**、**视频文件只读**。

## 一、不可变边界（本轮全程遵守）

### 2.3 检索升级（M2）

| 文件                       | 改动                                                                 |
| ------------------------ | ------------------------------------------------------------------ |
| `src/store/search.rs`    | **新建**：`split_terms`（支持引号短语）、`escape_like`、`keyword_clause`、`fts_ready`、`matching_ids` |
| `src/commands/media.rs`  | `LIST_WHERE` 改为含 `/*__KEYWORD__*/` 占位符，按词项数动态展开                      |

**策略是「并集」不是「替换」**：`LIKE`（保证正确性）∪ `FTS5`（加速）。
FTS5 不可用时（SQLite 可能没编进去）或词项不适合时**自动回落纯 LIKE**，结果一致。

⚠️ `escape_like()` 里**先转义 `\` 自身**再转义 `%` / `_`，否则刚加的转义符会被二次转义。

### 2.4 缓存与增量扫描（M3）

| 文件                    | 改动                                                     |
| --------------------- | ------------------------------------------------------ |
| `src/store/cache.rs`  | **新建**：`provider_cache` 表读写，TTL 7 天，只缓存**成功**响应         |
| `src/core/diff.rs`    | **新建**：`Fingerprint { size, mtime }` 判定「这条变没变」           |

⚠️ **增量扫描必须是「遍历全量、只过滤写入」**，不能跳过遍历——否则
`build_folder_stats` 的目录共识统计不完整，类型判定会翻案。

**缓存已接入刮削链路**（在 `commands` 层旁路，provider 的签名与优先级一行没改）：
`cached_detail`（TMDb 详情）、`cached_search`（TMDb 检索）、
`cached_season_episodes`（整季单集列表）三个包装函数，命中就省一次网络请求。

验证方式是「用**空 API Key** 构造客户端」——这种客户端真发请求必然失败，
所以「调用成功且拿到预置值」只能说明数据是**从缓存里读出来的**
（见 `cached_detail_serves_from_cache_without_network` 等 5 条用例）。

⚠️ **增量扫描仍未接线**（`core/diff.rs`）：见 §七。

**已接线**：扫描、刮削、NFO 导出、NFO 导入四类任务，在发旧事件的同时**并行**
发一条 `job-progress`（B8：旧事件不删不改，前端可以慢慢迁移）。
两者共用同一批调用点，映射是忠实的——结束态从旧结构自己的
`finished` / `cancelled` / `phase == "出错"` 推出来，不引入新的状态判断。

**数据源开关已接线**：新增设置项 `disabledProviders`（JSON 数组，只认注册表认识的 id，
脏值一律过滤），`Providers::load` 按它过滤。关掉 TMDb 时链路走**豆瓣接管**而不是报错。
设置项在「设置 → 数据源开关」有真实 UI 入口（后端加了设置就必须有可达的界面）。

⚠️ 顺手拆掉一处隐患：`scrape_one` / `douban_takeover` 原本单独收一个 `tmdb_key` 参数
来判断「TMDb 能不能用」，这和装配 provider 时读到的设置是**两个真相来源**。
现在统一由 `p.tmdb_on` 回答，参数删掉。

### 2.7 ffprobe 只读探测（M6）

| 文件                       | 改动                                           |
| ------------------------ | -------------------------------------------- |
| `src/provider/probe.rs`  | **新建**：只读调用 ffprobe 取分辨率 / 时长 / 编码；不可用时整段跳过 |

⚠️ **ffprobe 必须最后做**：`duration` 恒 NULL 时 R11（时长信号）从未生效；
一旦生效，`duration ≥ 100 分钟` 给 `movie +2`，足以把 Unknown 翻成 Movie。
所以它是**行为变更**，必须放在其它迁移稳定之后。

**本模块已实现但刻意未接入扫描流程**，模块头部有 `#![allow(dead_code)]` 并写明原因
（见 §七）。不接入 = 诊断页显示「ffprobe 不可用 / 可用」，但没有任何一行扫描逻辑会用到它。

### 2.8 依赖倒置（B3 修复）

`core/scanner.rs` 原本直接调用 `commands::settings` 与 `provider::llm`——两处**既成的反向依赖**。
做法：在 `core` 定义 `NameEnhancer` trait，由 `commands/media.rs` 实现 `LlmEnhancer`
并作为 `Option<&dyn NameEnhancer>` 注入 `import_reported`。

## 四、视频文件只读：每项能力怎么做到「不碰文件」

| 能力                | 落点                                     | 为什么没碰视频文件                             |
| ----------------- | -------------------------------------- | ------------------------------------- |
| 观看状态 / 续播 / 连播    | `playback_state` 表                      | 纯数据库读写；连播把**多个路径直接作为参数**交给播放器，**不生成临时 `.m3u8`** |
| NFO 导出            | 新建 `xxx.nfo` 旁车文件                       | 只**新建**；`overwrite` 默认 false；`write_nfo` 有**双保险**拒绝视频路径（目标路径带视频扩展名直接拒） |
| NFO 导入            | 只读 `.nfo`                              | `fill_metadata` **只补空字段**，已有标题/海报不会被顶掉 |
| 技术信息探测            | ffprobe **只读**调用                        | 只用 `-show_streams` / `-show_format`，从不指定输出文件；探测失败静默跳过 |
| 数据库备份             | `VACUUM INTO`                          | 目标文件**已存在时后端直接拒绝**，绝不覆盖旧备份             |
| 元数据缓存             | `provider_cache` 表                      | 缓存的是 API 响应，与文件无关                      |
| 检索索引              | FTS5 外部内容表 + 3 个触发器                     | 索引的是数据库里的文本列                           |
| 类型改判（R1）          | 只改 `media.type` + `type_audit`          | 只动数据库列                                 |

**验证方式**：`share::nfo::tests::refuses_to_write_over_a_video_file` 与
`write_nfo_skips_existing_file_by_default` 两条用例直接锁住「绝不写到视频路径上」
与「默认不覆盖」这两条底线。

## 五、做不到的事（需确认）

### 秒级续播：本期无法实现，已改为集级

- **限制**：本软件调用**外部播放器**（PotPlayer）播放。进程一旦拉起就与本应用无关，
  播放位置**不会回传**，无法得知「看到第 3 分 12 秒」。
- **已做的**：`position_secs` / `duration_secs` 字段**预留**在 `playback_state` 表里，
  API 与 store 都留了手动填写入口，但**不做任何自动采集**（不造假数据）。
  「继续播放」的语义明确为「播下一个未看集」。
- **替代方案（待确认）**：
  1. **内嵌播放器**（自绘解码 / 渲染，如 `libmpv` + 自绘窗口）：能拿秒级进度，
     但会**改动播放主流程**，与 B1「主体功能不变」冲突，需要单独立项评估；
  2. **读播放器的历史文件**（PotPlayer 有自己的播放记录）：侵入用户播放器目录、
     格式不公开、版本一变就失效，不做；
  3. **保持集级**（当前方案）：零改动、零风险，代价是没有秒级精度。

**当前选择 3，等确认后再决定是否走 1。**

## 七、仍未做的（规划里有、本轮未落地）
